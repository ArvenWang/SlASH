# Project SlASH — Redesign V2 PRD

> 状态：当前产品事实源  
> 版本：v2.0  
> 更新日期：2026-08-13  
> 优先级：本文件高于旧版 `FULL_GAME_DESIGN.md`、`FULL_GAME_ACCEPTANCE.md` 与 `FULL_GAME_PRODUCTION_PLAN.md`。旧文档仅保留历史规则和已实现内容，不再决定玩家流程、界面和视觉方向。

## 1. 本轮目标

把当前“系统全部外露的规划游戏”改成一款连续、直接、低文字的动作 Roguelite。近期按以下顺序交付：

1. 通关后三选一获得技能；
2. 删除完整技能树、路线选择和冗余结算，简化全部玩家界面；
3. 将旧场景替换为干净、铺满视野的高台平面，并拉远镜头；
4. 后续将角色替换为三角形主角、方形敌人，并接入真实重力和持续可见运动。

本轮不是给旧页面换皮。Run 编排、UI 信息架构、场景表现和角色物理都按新边界迁移。

## 2. 已锁定的玩家流程

```text
启动页
  → 开始
  → 自动选择并进入战斗
  → 通关
  → 三选一
  → 选择后立即生效
  → 自动进入下一场战斗
  → Act Boss
  → 下一 Act
  → 最终 Boss
  → 极简胜利 / 失败
```

### 2.1 启动页

- 用户不操作时永久停留，不自动开战。
- 默认只显示：`开始游戏`、有有效存档时的 `继续游戏`、`设置`。
- Boss 练习、档案、协议、威胁等级等不得占据主操作区；是否保留为二级入口以后单独决定。
- 不展示系统说明、内容数量、Seed、技能树结构或开发术语。

### 2.2 战斗之间

- 普通关卡和 Act Boss 通关后，直接出现三张技能卡。
- 不经过独立统计结算页。
- 玩家必须且只能选择一张；选择后立即写入本局构筑。
- 短暂确认反馈后自动进入下一关，不让玩家选择下一关。
- 最终 Boss 通关后直接进入胜利页，不再发放无意义奖励。

### 2.3 失败与胜利

- 失败页只显示：`本局结束`、`再来一次`、`返回主页`。
- 胜利页只显示：`通关`、`再来一次`、`返回主页`。
- 详细统计、Seed、路线、协议和完整构筑不出现在默认页面。

## 3. 技能获取 V2

### 3.1 玩家可见规则

- 每次符合奖励条件的关卡结束后恰好生成 3 个候选技能。
- 每张卡最多显示两行信息：技能名；一行直接结果。
- 默认使用简体中文。技能名可以单独使用英文，但不得使用“中文 / ENGLISH”并排格式。
- 不显示完整技能树、节点连线、点数、层级、前置、触发、限制、概率公式或后台标签。
- 已拥有且不可叠加的技能不会再次出现。
- 没有合法候选时必须使用正式定义的替代奖励，不得出现空卡或假按钮。

### 3.2 后台规则

- 现有技能 Definition、Gameplay Hook 和稳定 ID 可以复用；“树”只作为后台依赖图和候选过滤器存在。
- 候选生成由 `Seed + 奖励序号 + 当前构筑 + 候选池版本` 决定，相同输入必须得到相同三选一。
- 每组候选必须包含 3 个不同技能，且每个候选在选中当刻均合法。
- 前置关系由系统过滤，不要求玩家阅读或手动规划。
- 稀有度、分支权重和保底属于内容配置，不写死在 UI。
- 选择命令只接受当前三张候选中的一个稳定 ID，并且只能结算一次。
- 选择完成后同步 `selectedUpgrades`，继续复用现有真实战斗 Hook。

### 3.3 当前技能内容边界

- 已确认方向：`交叉处决`、`残响斩`、`杀意`。
- 保留观察：`回返斩`，在规则重新确认前不写入已确认池。
- 已否决：`擦身强化`、`死亡标记`、`双路径`，不得重新包装后加入。
- 现有其余技能可作为“已实现候选内容”保留，但不能因为已有代码就视为用户已确认；后续逐批做内容取舍。
- `交叉处决` 的 2.5 秒、`残响斩` 的 0.4 秒只属于初始调参，不是不可修改的最终值。

## 4. 后台 Run Director

- 现有 Seeded Route Graph 可以继续生成内容顺序，但不再渲染给玩家。
- 下一节点由 Director 自动选择，输入包括 Seed、Act、当前层、最近遭遇、当前构筑和难度约束。
- 自动选择必须遵守内容多样性、难度爬坡、Boss 可达和确定性要求。
- Event 与 Forge 不再作为独立玩家页面。需要保留的效果以后只能进入稀有三选一、自动规则或独立确认过的新流程。
- Challenge 可以作为关卡内部规则存在，但只显示完成战斗所需的最短提示。
- Route、Director 决策和奖励候选继续写入 Replay；玩家不需要看见它们。

## 5. UI V2

### 5.1 信息原则

- 一个页面只有一个主要任务和一个主要动作。
- 玩家界面默认单语言；禁止斜杠式双语标题。
- 删除解释系统如何工作的文字。
- 删除 `Draft`、`Committed`、`SP`、`Seed`、`Effect`、`Trigger`、`Limit`、`Prerequisite`、压力值、内部 Encounter ID 等开发信息。
- HUD 只保留生命、能量、大招是否可用和完成当前战斗所需的信息。
- 能量达到 100 后，空格触发 Vector Focus；该能力必须继续真实可用。

### 5.2 明确移出正式主流程

- 完整技能树；
- Run Map 和路线卡；
- 下一关选择；
- Planning Board；
- Forge 全树重接页；
- Event 长文二选一页；
- 独立节点结算页；
- 默认展示的完整胜负统计；
- 开场 `INBOUND`、原始 Wave ID 和遮挡战场的大标题。

## 6. 场景 V2

- 战斗空间是一个干净的高台平面，视觉平面尺寸大于镜头覆盖范围。
- 正常战斗画面不出现城市、铁轨、列车、雨雾、维修架或旧平台外部结构。
- Gameplay 边界与视觉平面分离：平面可以铺满画面，但仍有确定的可行走范围、障碍碰撞和坠落规则。
- 保留当前斜俯视方向，初始可视世界范围相对当前至少扩大约 1.5 倍，并根据画幅自动适配。
- 平台精度来自材质、光照、边界反馈和战斗痕迹，不靠堆叠背景物件。
- 新场景通过独立 Environment Provider/Profile 装配；替换场景不得修改 Encounter、Spawn、Ability 或 Replay 规则。

## 7. 角色与物理 V2（后续里程碑）

- 主角正式外观为方向清晰的三角形几何体，推荐三角柱或三棱楔体。
- 敌人正式外观以方盒几何体为基础，通过尺寸、层数、颜色、倒角和运动节奏区分类型。
- V5R GLB、骨骼动画、武器插槽和刀模型退出正式生产路径；文件暂不删除，作为历史资产保留。
- 每个动态角色必须拥有真实高度、垂直速度、重力、落地/支撑状态。
- 悬浮由重力、支撑力和阻尼共同产生；死亡后关闭支撑力并真实下坠。
- 所有活体即使不移动也必须持续有可见运动。移动、预警、攻击、受击和死亡分别驱动旋转、倾斜、压缩、拉伸和颜色反馈。
- 角色外观由可替换 Provider 创建；Gameplay 只持有物理和战斗事实，不依赖 Three.js Mesh 或具体模型。

## 8. 保留、迁移与废弃

### 保留

- 120Hz 固定步长与确定性基础；
- Dash、Charged Dash、Vector Focus、能量和真实技能 Hook；
- 敌人行为、攻击、碰撞、护甲、Projectile、Obstacle、Hazard、Encounter 与 Boss 规则；
- Seed、Replay、Save 的版本化基础；
- Gameplay 不反向依赖 Presentation 的架构门。

### 迁移

- Route Graph → 后台 Run Director；
- Skill Tree → 后台技能依赖图与奖励池；
- Skill Point Reward → 三候选奖励状态；
- Planning / Reward → 单一 `upgrade-choice` 阶段；
- Event / Forge → 暂停玩家入口，后续按新流程重新设计；
- Scene Runtime → 可替换的 Clean Arena Provider。

### 废弃

- 点数制玩家分配流程；
- 玩家显式选路；
- 完整树、完整地图和完整规则说明；
- 把页面内容数量当成体验合格的旧 UI 验收；
- 只检查动画 Clip 正在播放、不检查实机可见运动的验收方式。

## 9. 实施顺序

1. 本文件、V2 验收标准和模块边界成为唯一事实源。
2. 新增确定性的三候选奖励状态与选择命令；先用现有技能 Hook 验证完整链路。
3. 把启动、战斗、三选一、胜负做成最小闭环；移除旧玩家可见流程。
4. 接入后台自动选关，迁移 Save / Replay 命令。
5. 替换为干净高台场景与自适应远景镜头。
6. 接入几何体角色和真实垂直物理。
7. 逐批重新确认技能、敌人、关卡与 Boss 内容。

每个小节只验证直接改动的链路；整体完成后再做一次完整 Run 验证。已通过且未被修改的系统不重复验证。
