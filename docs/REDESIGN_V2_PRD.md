# Project SlASH — Redesign V2.1 PRD

> 状态：当前产品唯一事实源
>
> 版本：v2.1
>
> 更新日期：2026-08-14
>
> 优先级：本文件高于全部 `FULL_GAME_*` 历史文档与 V2.0 口径。旧内容只能作为实现参考，不能继续决定正式玩家流程、技能数量、角色、敌人、Boss 或视觉方向。

## 1. 产品目标

交付一款短而完整、低文字、强动作反馈的几何体动作 Roguelite：

- 玩家不操作时停在启动页；开始后直接进入战斗。
- 每场战斗结束只做一次三选一，不展示技能树、路线或结算报表。
- 主角、敌人、障碍、射弹和 Boss 统一使用精致几何体语言。
- 冲刺路径必须同时是可见攻击范围和真实击杀范围。
- 普通敌人保持一击必杀；Boss 明确打破该规则，拥有生命值、血条和分阶段受击窗口。
- 所有活体始终有姿态与运动；跳跃、砸地、分裂和坠落使用真实垂直物理。
- 删除旧模型、刀、血液、骨骼动画、旧技能海和旧 Boss 的正式运行路径，不保留双轨产品。

本轮不是给旧版换皮，而是压缩内容、统一规则和表现，并把每个留下的机制做到可读、可玩、可验证。

## 2. 一局结构

### 2.1 固定短局

- 一局共 3 个章节，每章 3 场战斗：2 场普通/精英遭遇 + 1 场 Boss。
- 全局共 9 场战斗、3 个 Boss、8 次技能选择；最终 Boss 后直接胜利，不再发奖励。
- 下一场由后台 Director 确定，玩家不看地图、不选路线。
- 每章只引入一个新敌人机制和一个 Boss 机制，避免同时堆叠大量规则。
- 标准完整局目标时长为 15–25 分钟；本轮优先保证机制清晰与完成度，不用内容数量拉长时长。

### 2.2 玩家流程

```text
启动页
  → 开始游戏
  → 战斗
  → 三选一
  → 自动进入下一战
  → 章节 Boss
  → 下一章
  → 最终 Boss
  → 极简胜利 / 失败
```

- 启动页无操作时永久停留。
- 默认只显示 `开始游戏`、有合法存档时的 `继续游戏`、`设置`。
- 失败页和胜利页只显示结果、`再来一次`、`返回主页`。
- 不显示 Seed、开发术语、完整统计、完整构筑、路线、协议、档案或系统说明。

## 3. 技能获取与构筑

### 3.1 装备和升级规则

- 正式技能池只有 5 个核心技能家族。
- 每局最多装备 4 个不同技能；第 4 个槽位填满后，未获得的第 5 个技能本局关闭。
- 每个技能最高 3 级。升级不占新槽位，也不产生第二个图标。
- 每场非最终战通关后恰好出现 3 张合法卡，共 8 次选择。
- 未装备且仍有空槽时，可出现新技能 I；已装备且未满级时，只出现它的下一级。
- 同一组卡中一个技能家族最多出现一次，不会同时出现 I、II、III。
- 候选由 `Seed + 奖励序号 + 当前四槽构筑 + 技能池版本` 决定；相同输入必须得到相同结果。
- 卡片只显示技能名/等级和一行直接结果。无完整技能树、前置、稀有度说明、公式或长描述。
- 不允许重抽、替换、背包、商店或局外永久数值成长进入本轮范围。

### 3.2 五个核心技能

| 技能 | I | II | III |
| --- | --- | --- | --- |
| 宽刃 | 冲刺宽度 +30% | 冲刺宽度 +55% | 冲刺宽度 +80% |
| 折射 | 障碍反射一次，保留 70% 距离 | 保留 90% 距离 | 保留 110% 距离且反射段不缩窄 |
| 交叉处决 | 两条路径相交时触发电光处决 | 交点范围 +35% | 交点范围 +70%，并清除交点内敌弹 |
| 残响斩 | 0.40 秒后沿原路径追加一次电光斩 | 残响宽度提升至 90% | 残响宽度提升至 110% |
| 杀意 | 单次冲刺每击杀 1 名敌人，收招缩短 8% | 每名 12% | 每名 16%，总缩短最多 60% |

规则说明：

- `宽刃` 改变引导线、路径光带和命中胶囊的同一个宽度参数，禁止只放大特效。
- `折射` 只反射一次；瞄准时必须同时显示入射段、碰撞点、反射方向和反射距离。
- `交叉处决` 仍只存一条历史路径；新路径与历史路径相交时消费两条线并触发一次效果。
- `残响斩` 只追加一次，不恢复旧版“双重残响”。
- `杀意` 只改变收招，不增加主动按键。
- 主动攻击永远只有普通冲刺、蓄力冲刺和满能量大招；全部三选一均为被动强化。

### 3.3 明确删除的技能内容

- 旧 27/28 项技能池、完整树、点数、Tier、前置展示和 Forge 重接全部退出正式产品。
- `弧线冲刺`、`双重残响`、`擦身强化`、`死亡标记`、`双路径`、旧大招加段和其余未经确认技能不进入 V2.1 奖励池。
- 历史 Skill ID 只有在承担上述五个家族的真实 Hook 时才可迁移；否则不得继续被正式 Registry、Save 或 UI 引用。

## 4. 主角

- 主角使用类似鼠标光标/小型飞船的尖头多切面楔体：前端长尖角、顶部隆起、底部龙骨收束，通过明/中/暗三组切面形成体积；禁止使用平面三角形直接挤出厚度，也不使用人形模型、骨骼、手、刀或武器插槽。
- 平面投影始终有一个明确尖角朝向鼠标世界坐标；待机、移动、受击和冲刺结束后也不得失去该朝向。
- `WASD` 提供 6.4m/s 的常速连续移动，方向按斜俯视镜头映射；允许八方向合成但必须归一化，松键后停止，不触发攻击。
- 普通移动可以是水平位移，但实体必须同时有悬浮、倾斜、轻微压缩/回弹和转向惯性；移动期间尖角仍朝向鼠标，不被移动方向夺走朝向控制。
- 冲刺仍沿输入路径突进并切断整条路径上的敌人；视觉路径、碰撞路径和回放路径共用同一组采样点。
- 基础冲刺速度为 86m/s，蓄力冲刺为 112m/s；大招三段整体执行时间限定在 720–1050ms，保持高速但必须肉眼可见三次穿梭与转折，禁止瞬移。
- 玩家在突进飞行或收招冷却期间再次按下鼠标时，系统缓存最新目标：快速点按在冷却结束自动执行基础冲刺；持续按住在冷却结束自动进入蓄力，并继续跟随鼠标更新目标。缓存输入必须进入 Save/Replay，不得只由页面延时模拟。
- 冷却期间缓存成功后立即显示偏暖色的下一段等宽引导，明确告知输入已经被接收；取消指针则清除该缓存。
- 普通敌人只要位于有效斩击带内且不处于明确无敌机制中，任意有效冲刺命中即死亡；不保留普通小兵多段血量或暗藏减伤。
- 切割不使用血液、肉块或尸体断肢。命中使用电光切面、几何碎片、短暂轮廓分离和消散。
- 主角的垂直高度仍由 Gameplay 重力状态决定；Presentation 不得把高度强制归零。

## 5. 敌人和障碍

### 5.1 首发敌人精简为五类

| 敌人 | 几何语言 | 核心行为 |
| --- | --- | --- |
| 追击体 | 单立方体 + 前向楔面 | 预警后直线冲锋 |
| 射击体 | 双立方体炮架 | 面向玩家发射几何脉冲 |
| 旋转体 | 交叉方块/多面体 | 旋转蓄力后释放扇形或径向攻击 |
| 分裂体 | 可拆组合体 | 被击破后分成两个更小、更快的单位 |
| 砸击体 | 重型多面体 | 起跳、空中停顿、落点预警、砸地产生几何冲击环 |

- 每类敌人通过轮廓、颜色、运动节奏和预警区分，不靠文字标签。
- 活着的敌人即使水平位置不变，也必须持续悬浮、呼吸式缩放或结构旋转。
- 射弹不是写实子弹，可以是发光棱柱、脉冲块或短束；必须有前向运动、可读碰撞体和消失反馈。
- 射弹、分裂和砸地必须保持确定性，并进入 Save/Replay 必要状态。

### 5.2 障碍

- 障碍使用柱体、斜面体和反射棱柱等几何体，通过颜色/粗糙度区分普通阻挡、可折射面和危险体。
- 障碍碰撞属于 Gameplay；材质与网格属于可替换 Presentation Provider。
- 反射棱柱必须给折射路径提供稳定法线，不允许表现方向与实际方向不一致。

## 6. 三个 Boss

### Boss 1：棱镜猎犬

- 由一个主楔体和两个侧方块组成，负责验证冲锋、转向预警和射击的组合。
- 核心窗口直接由完成一次完整冲锋循环触发，不依赖隐藏单位死亡。

### Boss 2：魔方堡垒

- 由可旋转、重组的方块阵列和唯一核心组成。
- 外层方块可分离成射击体或旋转臂；打破指定外层后核心必须进入可攻击状态。
- 胜利只由唯一核心生命归零决定。外层单位数量、丢失引用或阶段切换不得让核心永久无敌。
- 必须覆盖旧版“击杀两个伴随单位后本体无法击杀”的回归场景。

### Boss 3：奇点王冠

- 由中心多面体、旋转环块和可跳起的重锤块组成。
- 依次组合旋转弹幕、分裂诱饵、跳跃砸地；每种攻击都有独立预警、执行和收招。
- 最终阶段可以加快组合节奏，但不得取消可读窗口或依赖不可见规则。

所有 Boss 共用统一合同：`telegraph → active → recovery/core-window → next`。任何阶段都有最长持续时间与保底转移，不允许无穷等待或不可达核心。

- Boss 不使用普通敌人的一击必杀。三个 Boss 各有明确 `currentHp / maximumHp`，基础冲刺、蓄力冲刺和大招按统一伤害表扣血。
- Boss 血条在 Boss 战期间持续可见；关闭核心时命中不扣血，并用几何护盾反馈说明原因，不依赖文字解释。
- 核心窗口内每次合法命中都必须扣除可预测的生命；生命归零立即结束 Boss，不再等待伴随单位、动画回调或下一阶段。

## 7. 场景和镜头

- Gameplay 可活动区域扩大为 240m × 144m（`x = -120..120`，`z = -72..72`）；移动、冲刺、射击、反射、Boss 机动和相机真实使用该尺寸，不能只缩小角色或拉远旧场地镜头。
- Environment 使用 360m × 216m 的连续地表覆盖相机视域。正常游玩不得出现活动方框、抬高甲板边唇、外部低位基底或人为边界光带，也不出现城市、铁轨、列车和雨雾等重背景。
- 相机保持斜俯视角并跟随主角；桌面局部视域约为 68m × 42m，玩家向任意方向移动时场地连续延伸，而不是把完整大场地压缩在屏幕中央。
- 普通冲刺、蓄力冲刺和大招单段均没有短距离上限：合法目标在 Gameplay 区域内时必须到达指针目标；只有真实障碍物和折射面可以提前改变路径。
- 普通遭遇保留广域出生，后续扩展内容时不得重新把敌人全部挤回旧中心区域。
- Resize 后重新计算局部构图，并保持主角、邻近敌人、射弹和预警可辨识。
- 渲染使用低金属度、高粗糙度的受控 PBR 材质、柔和环境光和方向光、接触阴影与有限 Bloom；不得在特定角度出现大面积爆白或镜面高光。
- 场景、角色、敌人、障碍和特效分别由 Provider/Registry 装配，未来替换模型不得改写 Gameplay。

## 8. 垂直物理与持续运动

- Player、Enemy 和需要跳跃/坠落的 Boss 部件拥有 `height`、`verticalVelocity`、`gravity`、`grounded/supported` 状态。
- 固定步中先施加重力，再处理支撑/落地；越出支撑区域后不得继续悬浮。
- 悬浮是有重力的平衡状态，不是把 Mesh 写死在固定高度。
- 分裂单位继承合法出生高度与速度；砸击体必须经历起跳、顶点、下落和着地四个可验证阶段。
- 同 Seed 和命令在不同渲染帧率下得到相同 Gameplay Hash。
- 表现层在 Gameplay 高度之上叠加很小的视觉呼吸，但不得篡改碰撞高度。

## 9. UI 与输入

- HUD 只保留生命、能量、大招可用状态和当前必要目标；Boss 战额外显示唯一 Boss 血条。
- 能量达到 100 后，空格进入 Vector Focus：敌人、Boss、射弹、出生与遭遇计时统一降至 16% 速度，3.5 秒规划倒计时仍按真实时间推进。
- Vector Focus 以主角屏幕位置为中心叠加径向红移/色散和红色脉冲环；不能只改色而不真实减速，也不能把全屏染成不透明红色。
- Vector Focus 依次规划三个落点；已确认线段持续留在地面，鼠标到下一点的待确认线段实时更新，第三点确认后沿同一组线段执行大招。
- Vector Focus 执行期逐段产生白色能量核、红青薄边、路径碎光、几何角色残影链、起点/转折冲击环与终点爆发；不能只留下规划线，也不能以瞬移代替过程。
- 大招开始时镜头锁定能容纳完整规划路径的构图中心，执行三段时不紧贴角色急转；仅保留轻度冲击感，结束后短暂停留再平滑恢复普通跟随。
- 冲刺引导使用全程等宽的攻击带，内部箭头/光纹持续向目标流动；外轮廓宽度必须真实对应命中宽度，禁止锥形收尖、静止矩形片或单像素细线。
- 长按蓄力时，引导带从基础击杀宽度连续扩大到 1.65 倍并同步变亮；预览宽度、执行命中宽度和回放路径必须同源。
- 满蓄冲刺必须有包裹角色的压力锥、强化尾迹、起步冲击和终点双层冲击波，与普通冲刺形成可辨识差异。
- 折射激活时完整显示两段带状路径和碰撞点；距离超限、无合法反射时不得显示假路径。
- 默认简体中文；技能名可全英文或全中文，但不得同项中英并排。
- 不显示完整技能树、路线、下一关、独立结算、内部 ID 或解释开发逻辑的文字。

## 9.1 敌人与 Boss 尺寸层级

- 普通敌人必须按机制形成可读尺寸梯度：分裂碎片最小，射击体/追击体接近基础尺寸，分裂体与旋转体更大，砸击体最大。
- Boss 主体、护盾与外围部件必须显著大于任一普通敌人；视觉尺寸与 Gameplay 碰撞半径同步，但接触伤害范围不能无限等同于全部装饰外轮廓。

## 10. 模块化和清理要求

- Gameplay 只保存物理、战斗、路径和状态事实，不持有 Three.js Mesh、材质或模型插槽。
- Primitive Character Provider、Enemy Provider、Boss Provider、Environment Provider 和 VFX Provider 可独立替换与释放。
- 未来换回 GLB 时只能新增 Provider/Registry 映射，不能把骨骼、Clip、手或刀重新写入 Gameplay。
- V2.1 交付前，旧 V5R、武器、血液/断肢、旧 27 技能池、四个旧 Boss 和旧场景不得再从正式入口可达。
- 对已失去全部生产和验证引用的旧代码、资产、脚本和样式进行删除；不能只用隐藏开关保留第二套正式系统。
- Save/Replay 使用新内容版本。无法无损迁移的旧存档明确提示版本不兼容并保留原文，不做静默近似迁移。

## 11. 实施顺序

1. 锁定本 PRD、V2.1 验收标准和模块边界。
2. 将 Run 压缩为 3 章 9 战，并落地 5 技能/4 槽/3 级/8 奖励规则。
3. 接入几何体主角、朝向、持续运动、带状引导线和电光切割。
4. 接入五类几何敌人、三类障碍、射弹和垂直物理。
5. 接入三个新 Boss，并封住魔方堡垒不可击杀回归。
6. 清除旧正式路径和失效验证，完成一次完整 Run 与最终视觉审查。

每个小节只验证直接修改的链路；整体完成后只做一次整体验收。已验证且未修改的范围不重复运行。
